Sequence Diagram – Purchase scan (Stock IN)

Source: docs/uml/03-sequence-purchase.mmd

sequenceDiagram
  autonumber
  actor SK as Storekeeper
  participant PWA as Mobile PWA
  participant API as API Server
  participant OBJ as Object Storage
  participant Q as Job Queue / Worker
  participant AI as Vision AI
  participant DB as PostgreSQL
  SK->>PWA: Choose "Purchase (Stock IN)", take 1..n photos
  PWA->>PWA: Quality check, compress, de-skew
  PWA->>API: POST /scans {type: purchase} + pages
  API->>OBJ: Store page images
  API->>DB: INSERT scan (status=PROCESSING), scan_pages
  API->>Q: enqueue extract(scanId)
  API-->>PWA: 202 {scanId}
  Q->>AI: extract(page images, JSON schema, product hints)
  AI-->>Q: header + lines + confidence
  Q->>Q: Validate qty×rate, Σlines vs total, normalise units
  Q->>DB: Match aliases / fuzzy match products
  Q->>DB: INSERT scan_lines, AiCallLog, status=NEEDS_REVIEW
  Q-->>PWA: notify (push / poll)
  PWA->>API: GET /scans/{id}
  API-->>PWA: lines + flags + photo URLs
  SK->>PWA: Correct rows, pick supplier, set prices for new items
  PWA->>API: PATCH /scans/{id}/lines (autosave)
  SK->>PWA: Confirm
  PWA->>API: POST /scans/{id}/confirm (Idempotency-Key)
  API->>DB: BEGIN
  API->>DB: create new products + aliases
  API->>DB: INSERT purchase_doc + doc_lines
  API->>DB: INSERT stock_movements (IN), update onHand, avgCost
  API->>DB: price_history + update purchasePrice
  API->>DB: ledger (supplier payable), audit_log
  API->>DB: scan.status=CONFIRMED
  API->>DB: COMMIT
  API-->>PWA: result (stock before → after, new products)

Sequence Diagram – Sale scan (Stock OUT + receipt)

Source: docs/uml/04-sequence-sale.mmd

sequenceDiagram
  autonumber
  actor SM as Salesman
  participant PWA as Mobile PWA
  participant API as API Server
  participant Q as Worker
  participant AI as Vision AI
  participant DB as PostgreSQL
  participant RCP as Receipt Service
  participant WA as WhatsApp / Printer
  SM->>PWA: Choose "Sale (Stock OUT)", add bill pages
  PWA->>API: POST /scans {type: sale} + pages
  API->>Q: enqueue extract(scanId)
  par each page in parallel
    Q->>AI: extract(page)
    AI-->>Q: lines + confidence
  end
  Q->>Q: merge pages, validate totals
  Q->>DB: match products, load onHand + salePrice
  Q->>DB: flag lines where qty > onHand
  Q-->>PWA: NEEDS_REVIEW
  SM->>PWA: Fix flagged rows, select customer, payment mode
  alt qty > stock and negative stock not allowed
    PWA-->>SM: Confirm blocked - reduce qty or record purchase
  else OK
    SM->>PWA: Confirm
    PWA->>API: POST /scans/{id}/confirm
    API->>DB: BEGIN, sale_doc + lines, OUT movements (COGS=avgCost)
    API->>DB: payment / receivable ledger, audit, COMMIT
    API->>RCP: build receipt (next receipt no.)
    RCP-->>API: PDF + link
    API-->>PWA: remaining stock, low-stock list, receipt
    SM->>WA: Share PDF / print thermal
  end

State Machine – Business day (daily closing)

Source: docs/uml/13-state-day.mmd

stateDiagram-v2
  [*] --> Open : first sale / scan of the day (opening cash = yesterday's counted cash)
  Open --> Open : sales, purchases, expenses, wasooli
  Open --> Counting : owner opens "Aaj ka hisaab"
  Counting --> Open : back (nothing saved)
  Counting --> Closed : counted cash entered, Din band karein
  Closed --> Reopened : owner reopens with reason (audit log)
  Reopened --> Closed : re-close, totals recalculated
  Closed --> [*]
